## Engine capabilities added for fidelity
- `creation.choices[].options[].fixes`: while an option is selected a field holds a value and is
  locked (e.g. a clan that sets Appearance to 0). The engine writes it when the option is chosen,
  refunds points spent on it, rejects other values (`choice.fixed_value`) and reports the holds in
  the choice availability so clients lock the control and say why. Mode `at_least` raises the
  field to a minimum that may still grow (e.g. a skill an origin trains). Held levels are given,
  not bought; leaving the option returns held fields to their default and refunds paid levels.
- Roll strategy `keep`: N dice, keep the K highest or lowest, both from formulas (Ordem
  Paranormal: a d20 per attribute point keeping the best; at 0, two keeping the worst).

- No source document is in the repository: every value is pending (`· a conferir`,
  `review_status: unverified`, SOURCE-REGISTER.md per package). Tests:
  `VampireV20PresetTest`, `VampireDarkAgesPresetTest`.
- Engine capabilities these presets lack (proposals, not implemented):
  1. A cost rule that applies only to some increments (`applies_when`: boolean formula over
     `current`/`new` and the sheet). Today "priority points pay Abilities only up to 3" and
     "creation Discipline points pay clan Disciplines only" price the other increments above any
     balance so the next rule (freebies) pays; an unaffordable dot then reports that price.
  2. Losing a trait in play without a refund (degeneration of Humanity/Path/Road, permanent
     Willpower): lowering a rating today refunds the budget that paid it, including XP. Proposed:
     `refund_on_decrease: false` per cost rule for the advancement phase, or a distinct
     `lose_rating` operation recorded in the history.
  3. A bounded pool modifier on declared rolls (e.g. `modifier: formula` for `pool`), so wound
     penalties and untrained-Ability rules apply on the server instead of being shown only.
